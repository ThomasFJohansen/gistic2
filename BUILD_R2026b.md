# Build GISTIC2 for MATLAB Runtime R2026b

Target: **MATLAB R2026b / MATLAB Runtime 26.2**, the latest release listed by
MathWorks on 2026-10-23. The MATLAB source and native helpers have been updated
for this target. Compilation and end-to-end validation are pending; no new
executable or claim that the reported AMD crash is fixed is included.

**Runtime release issue:** MathWorks currently advises RHEL/SUSE-based Linux
distributions to wait for **R2026b Update 1** because the initial R2026b Runtime
has an issue on those distributions. Check the current
[Runtime download page](https://www.mathworks.com/products/compiler/matlab-runtime.html)
before installing. This is separate from GISTIC2's older-runtime crash.

## Compile

Use **Linux x86-64 MATLAB R2026b**, MATLAB Compiler, Statistics and Machine
Learning Toolbox, and a [supported C compiler](https://www.mathworks.com/support/requirements/supported-compilers.html).
A Windows or macOS MATLAB build will not produce a Linux executable.
MATLAB Runtime alone cannot compile the source.

```bash
git clone --branch matlab-r2026b --recurse-submodules https://github.com/ThomasFJohansen/gistic2.git
cd gistic2
```

In a fresh MATLAB session, with this repository as the current directory:

```matlab
mex -setup C
build_gistic
```

Once the C compiler is configured, the noninteractive equivalent is:

```bash
matlab -batch "build_gistic"
```

The build writes a new `build/R2026b/` directory. It refuses to overwrite an
existing build. For another attempt, choose a new absolute output path:

```matlab
build_gistic('/absolute/path/to/gistic-r2026b-build2')
```

The build stages the MATLAB source, rebuilds both SegArray C helpers, runs small
migration checks, and invokes MATLAB Compiler. The output contains:

- `gp_gistic2_from_seg`: newly compiled executable.
- `run_gp_gistic2_from_seg.sh`: Runtime launcher generated by MATLAB Compiler.
- `gistic2`: forwards the Runtime path and GISTIC arguments to that launcher.
- `build.log` and `MATLAB_VERSION.txt`: compiler output and exact MATLAB version.
- `matlab/`: the effective source tree, including rebuilt MEX files.
- `examplefiles/`, `refgenefiles/`, and both original license files.

Keep all generated deployment files together when copying the build to another
machine. Do not use the old executable in `support/` or the historical
`support/release_gistic_source.sh` release script.

## Run the compiled application

Install **R2026b Runtime at the same update level as the compiler, or newer
within R2026b**. Point `MATLAB_RUNTIME` at the actual version directory containing
`runtime/`, `bin/`, and `sys/`:

```bash
export MATLAB_RUNTIME=/path/to/MATLAB_Runtime/R2026b
mkdir -p /path/to/new-results
/path/to/build/R2026b/gistic2 \
  -b /path/to/new-results \
  -seg /path/to/input.seg \
  -refgene /path/to/reference.mat
```

Append the same GISTIC analysis options as your previous run. The launcher sets
no CPU affinity, numerical thread limits, or historical MKL workaround variables.
To test unrestricted execution, start from a shell without those settings inherited
from an earlier workaround. Keep the JVM enabled: a utility uses Java Hashtable.

## Source changes

- Replace nonscalar colon bounds (`1:size(x)`) in seven SegArray methods and
  `reorder_D_rows` with scalar element counts. These expressions error in
  MATLAB R2025a and later. The affected values are vectors; the repmat argument
  loop now also handles every argument instead of only the first cell.
- Use graphics objects and `isgraphics` for subplot handles and arrays of plot
  objects. Missing plots use graphics placeholders instead of numeric NaNs.
- Remove the obsolete `zbuffer` renderer selection. Export PDF/EPS with the
  explicit `print(...,'-vector')` option; renderer properties no longer control
  export in R2025a and later.
- Preserve GISTIC's `unique(...,'legacy')` behavior directly, without parsing
  MATLAB's version number as a decimal.
- Rebuild `cosort` and `sumranges` with the interleaved C Matrix API
  (`mxGetDoubles`, `mex -R2018a`), native-size indices, input validation, and safe
  handling of calls with no outputs. Keep merge tie order and accumulation order.

Updated dependency files live in `source/`, including `source/@SegArray/`.
They are overrides of the pinned upstream `snputil` submodule
(`cf3172b858c6ceea1688816e632228c89ba80e89`), with original license headers retained.
The build copies `snputil` first, then overlays `source`, into **one** MATLAB
directory. This avoids ambiguous duplicate helpers on the MATLAB path. It copies
only `.m` files and builds the updated C files, so no old MEX binaries are reused.
It also omits `snputil/newline.m`, which shadows MATLAB's built-in while returning
literal backslash sequences; its single use is diagnostic logging.

The scoring, peak detection, histograms and statistical methods are retained.
`histc`, `strmatch`, and `nanmean`/`nanmedian` remain available in R2026b. Blindly
replacing them would risk changing bin boundaries, matching, or SegArray dispatch.

## Checks and remaining validation

Local checks passed: independent MATLAB syntax parsing, shell syntax, and 2,000
deterministic native-helper comparisons against the original C implementations.
The C checks used a small test substitute for the MEX API with address/undefined
behavior sanitizers; they do **not** validate MATLAB's real MEX ABI.

`tests/matlab/test_matlab_compatibility.m` runs during your build. It checks
legacy unique indices, native-helper results/errors, the affected SegArray
operations, Java matching, and figure export. It has not been executed here:
this environment has no licensed MATLAB installation. The build itself is also
unexecuted here.

After compilation, run your original failing dataset with the same inputs and
options and compare scientific outputs to the successful old run. Completing
that test is required before describing the AMD crash as resolved.
